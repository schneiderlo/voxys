# Voxys bug ledger

This ledger records reproduced defects, their fixes, and the checks that prove
the fix.

| ID | Severity | Status | Defect | Evidence and fix |
|---|---|---|---|---|
| VOX-001 | High | Fixed | Live `directionalSineScale` changed GPU waves but not the CPU water sampler used by CPU physics. Buoyancy could drift away from the rendered surface. | `WaterSimulation::updateCpuWaveCache` now evaluates and differentiates the same scaled temporal coefficients as `water_fft.wgsl`. Covered by `WaterSimulationGPUTest.BuildsAndDispatchesCompleteOceanPipeline`. |
| VOX-002 | High | Fixed | A failed `Application::init` could retain partially-created GPU/application resources because `shutdown()` returned early while `initialized_` was false. | Every failed initialization stage now rolls back. `shutdown()` also detects partial state instead of relying only on `initialized_`. |
| VOX-003 | High | Fixed | Zero or negative configured window dimensions could reach aspect-ratio division and unsigned GPU extents. A zero heightmap extent also reached terrain creation. | `Application::init` rejects invalid extents before creating a window or GPU object. Covered by `ApplicationTest.RejectsInvalidDimensionsBeforeCreatingResources`. |
| VOX-004 | Medium | Fixed | Procedural heightmap allocation multiplied two `uint32_t` extents before converting to `size_t`, allowing wraparound before allocation. | Allocation and indexing now widen before multiplication. |
| VOX-005 | High | Fixed | Non-finite water spectrum, time, position, strength, or coast parameters could survive clamping and inject NaNs into GPU waves or CPU buoyancy. | Spectrum fields now fall back to the last valid value before clamping. Invalid samples, updates, and coast rebuilds fail safely without replacing live resources. Covered by `WaterSimulationGPUTest.BuildsAndDispatchesCompleteOceanPipeline`. |
| VOX-006 | High | Fixed | Browser focus loss could strand movement keys, mouse buttons, and pointer-lock state because browsers may omit their release events. The renderer inspector also retained its forwarded-key set. | The WASM window-blur callback now resets all held and queued engine input. The inspector releases and forgets forwarded keys on blur or tab hiding. Covered by `InputTest.FocusLossClearsHeldAndQueuedInput`. |
| VOX-007 | High | Fixed | WASM document callbacks kept a global pointer to a destroyed `Input`, allowing a later browser event to dereference freed memory during shutdown. | The WASM `Input` destructor clears the callback target and releases capture. |
| VOX-008 | Medium | Fixed | The documented ASan test configuration could not run: GCC emitted an optimizer false positive from `libstdc++`, and LeakSanitizer searched for its suppression file beside each test binary instead of in Bazel runfiles. | The ASan profile disables that one compiler diagnostic while retaining runtime instrumentation, and uses the stable executable-relative path to the workspace suppression input. |
| VOX-009 | High | Fixed | `Input` was publicly movable even after native lambdas or WASM globals captured its address. Moving it left callbacks targeting the moved-from object and enabled use-after-free. | `Input` is now immovable, matching its stable-address callback ownership. Covered by `InputTest.CallbackOwnerHasStableAddress`. |
| VOX-010 | High | Fixed | A failed live water-spectrum rebuild released the working bind groups before its replacements existed. One allocation failure could leave the ocean reporting itself initialized while dispatching null or mismatched resources. | Spectrum buffers, CPU modes, and every replacement bind group are now built as a transaction. The old set is released only after the entire new set succeeds; `isInitialized()` also verifies the complete dispatch state. The successful rebuild path is covered by `WaterSimulationGPUTest.BuildsAndDispatchesCompleteOceanPipeline`. |
| VOX-011 | Medium | Fixed | Water startup allocated two history buffers, a storage texture, a shader, a pipeline, and bind groups for a foam simulation that was never dispatched or sampled. | VOX-012 | Medium | Fixed | Renderer startup allocated and uploaded two placeholder textures that were never bound. Their allocations were unchecked, so an out-of-memory null handle could also be passed straight to WebGPU. | Removed both dead placeholder allocation paths and their lifetime state; `TerrainTextures` already guarantees the bound fallbacks. |
| VOX-013 | Medium | Fixed | A press and release delivered between two frames preserved the press edge but lost the release edge. Fast key taps and mouse clicks therefore gave contradictory transition results. | Added per-frame release accumulators for keys and buttons, matching the existing press accumulators. Covered by `InputTest.QuickKeyTapPreservesBothEdges` and `InputTest.QuickMouseClickPreservesBothEdges`. |
| VOX-014 | High | Fixed | Browser pointer lock could be denied or released by Escape/the browser while `Input::captured_` stayed true. Mouse-look then used relative-motion semantics even though the pointer was free, and button releases could remain stuck. | Pointer-lock request failures now roll back capture, and a pointer-lock-change callback synchronizes state and clears buttons on loss. The WebAssembly target compiles this path. |
| VOX-015 | Medium | Fixed | The file/CLI `resolution_scale` setting was parsed and copied into `ApplicationConfig`, but never affected a render target. Users paid full-resolution GPU cost at every configured scale. | Startup and resize now scale the swapchain and all framebuffer-sized targets consistently. Invalid or non-finite scales are rejected before GPU creation. Covered by `ApplicationTest.RejectsInvalidDimensionsBeforeCreatingResources`. |
| VOX-016 | High | Fixed | `LockstepWorld::setBodies` cleared and partially replaced the authoritative simulation before validating an incoming body set. A rejected checkpoint or network state silently destroyed the last working deterministic state. | Incoming bodies are now validated before any mutation. Covered by `Lockstep.RejectedBodyUploadPreservesWorkingState`. |
| VOX-017 | High | Fixed | Frame and screenshot submission passed unchecked null WebGPU encoders/command buffers into later calls. Screenshot failures also leaked GPU handles, overflowed 32-bit readback sizes, always interpreted pixels as BGRA, and captured the unused surface instead of the offscreen benchmark target. | Submission now stops safely on allocation failure. Screenshot layout arithmetic is widened and checked, RGBA/BGRA formats are handled explicitly, benchmark captures use the rendered texture, and every success/failure/timeout path releases its handles without leaving callback userdata dangling. |
| VOX-018 | High | Fixed | Resizing application-owned benchmark and depth targets destroyed the working target before its replacement texture and view were known to exist. | VOX-019 | High | Fixed | Failed `gpu::Context` initialization retained instances, surfaces, adapters, devices, or queues. | VOX-020 | High | Fixed | Dawn adapter/device requests returned after a one-second timeout even though the legacy WebGPU request could not be cancelled and still held a pointer to stack callback state. A late callback wrote into a dead stack frame. | Dawn startup now pumps events until each non-cancellable callback completes, keeping its userdata alive for the full API-mandated lifetime. |
| VOX-021 | High | Fixed | `RaycastPath::resize` and `BlitPath::resize` released all working framebuffer textures and bind groups before allocating replacements. Any failed texture/view in the multi-resource rebuild left the renderer permanently incomplete. | VOX-022 | High | Fixed | Live raycast/blit binding changes released the complete working bind-group set before creating all replacements. Failure in the second, third, or fourth group both leaked earlier replacements and disabled later rendering. | Raycast and blit binding sets are now assembled in temporary handles, cleaned on partial failure, and swapped into service only as a complete set. |
| VOX-023 | High | Fixed | Application startup accepted non-finite or mathematically invalid terrain, camera, water, timing, physics, and automation values. | VOX-024 | High | Fixed | When native surface negotiation rejected the preferred color format, `gpu::Context` selected a supported fallback but terrain/blit pipelines still used the original format. | VOX-025 | Medium | Fixed | Reinitializing one `Application` object retained frame statistics, benchmark/tour state, timing queues, debug/controller modes, and camera recordings from its previous run. | A fresh initialization now resets all run-scoped CPU state before creating subsystems. |
