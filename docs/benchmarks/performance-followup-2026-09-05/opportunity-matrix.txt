Radix candidate proof sketch (before implementation): for digit d, histogram h[b,d] is unchanged. Partition [0,B) into 64 contiguous ordered chunks. Each lane computes its chunk total; the workgroup scan computes exactly the sum of all earlier chunks. Rescanning its chunk writes O[b,d]=sum(h[k,d],k<b), which is the original offset. The last rank writes total T[d]. The next dispatch scans T in original digit order to produce D[d]=sum(T[k],k<d). No output locations have multiple writers. Dispatch ordering makes totals visible before digit-base scan. All operations are integer additions (associative modulo 2^32, and real counts fit the existing capacity); no float expression or stable within-block rank changes. Therefore final scatter destinations and all four words of each sorted record are identical. B<=128 retains original prefix; the new preliminary dispatch returns uniformly without side effects. Empty indirect dispatch retains existing outputs. Large capacity with few active items needs performance validation because an extra no-op dispatch still has cost.
