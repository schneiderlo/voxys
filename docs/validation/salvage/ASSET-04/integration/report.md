## Failures retained and fixed

1. Native attempt 01 showed the ground because the legacy LEGO initialization
   overrode the inspection camera with the character controller. Both entry
   paths now preserve the configured free-fly inspection camera. Attempt 02
   visibly shows the four authored models.
2. Browser inspection attempt 01 used `freefly` in its assertion; the actual
   established serialization is `free-fly`. Attempts 02/03 correct the test.
3. Browser loss attempt 01 revealed a product bug: Closure renamed
   `globalThis.voxyDeviceLost` inside the independently compiled WASM glue. The
   browser page's real notification could not reach C++. The bridge now uses
   bracket notation to preserve the external property name.
4. The exported initialized query previously returned true while a shut-down
   Application object still existed. It now checks `isInitialized()`. A terminal
   update also skips rendering/presentation of one last invalid frame. Drained
   inspection state no longer incorrectly reports `busy`.
5. Loss attempt 02 passed the actual shutdown assertions but the outer harness
   rejected the expected application failure log. Attempt 03 permits precisely
   that message plus the genuine destroyed-device notice; other errors still
   fail the run.
6. Pinned native wgpu supports only Validation and OOM error scopes, despite its
   header declaring Internal; the first real test aborted on Internal. It also
   implements DeviceDestroy as a no-op. The owner accounts for that backend
   difference; native forwarded-loss and actual browser loss evidence are
   explicitly separate. Details and source links are in the owner design.
7. The later ID-order test found a second product bug: both sidecar bindings and
   admitted meshes sort by durable ID. The selector and earlier design/review
   prose incorrectly assumed sidecar threshold order. IDs 91/7/42 reproduced

  passes in both native builds and actual WASM. Its first strict builds also caught test-only
   stream-reading warnings, implicit float promotion and an older JSON library's
   unsupported unsigned-byte iterator under libc++; those test inputs are fixed
   without suppressing warnings. The earlier camera-setting suspicion did not
   explain the ID-order failure; the actual parser ordering did.
