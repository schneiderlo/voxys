# Actual Cove cache: deferred prototype

Production was not modified by this prototype. It has not been promoted. No FPS benefit is established.

The current dirty-frame order shades legacy material into the RGBA16Float background, then shades actual Cove material again in the live terrain pass. The candidate bakes the actual Cove helper after the current fixture environment is bound. Above-water pixels with current scene visibility exactly 1 copy that result; shadowed pixels and underwater caustics keep the original live helper. Cached frames could skip almost all Cove material lighting, while refreshed frames could remove duplicate legacy shading.

`candidate.patch` contains the four-source CPU/shader change. `source-identities.json` records original and candidate hashes; full files are preserved under baseline/ and candidate/. The shader-only prototype must not be substituted into the current game without the CPU changes.

`integration-tests.patch` extends the existing real native Cove composition fixture with a dedicated lifecycle test. Its source is prepared but uncompiled and unexecuted. Checks cover same-content rebakes and view identity, in-place source content changes, abandoned environment/background encoding and retry, admission/Leave legacy seed transitions, exposure-only changes, ambient changes and advancing underwater caustics. Existing composition tests remain available unchanged through the helper's default parameter.

The separate full-entry oracle is in ../intel-cove-actual-cache-oracle/. It exports 33 paired cases/66 streams, executing the existing original background/live entries against the actual-Cove background/cache-copy entries. Only final live RGBA16Float/R32Float outputs are compared; the intentionally changed cache is retained as an exercised-path control. All uploaded bytes match except the explicitly normalized private cache-valid lane. Source, fixture, blob and output hashes are recorded. Intel execution is blocked by the new environment's WSL interop restriction (`UtilBindVsockAnyPort: socket failed 1`). Any software-Vulkan result is supplemental and cannot substitute for Intel acceptance or game timing.

The private validity flag uses only waterMotion.w. The repository audit finds no current w consumer beyond initialization, static canonicalization and finite-value validation. CPU upload patches that single four-byte GPU lane without changing public camera state. Exposure remains presentation-only; ambient RGB and fog RGB remain cache keys.

Environment bakes currently update the same textures. The patch publishes three fresh, identically described sampled views after each successful encodeBake, so the existing pointer-identity callback invalidates the cache without changing the public views struct. Old material bind groups retain valid views of the same backing textures. This rare-bake allocation strategy still needs native lifetime/error tests and measurement; an explicit content revision is an alternative if handle churn is undesirable.

The current RenderFrameGuard invalidates BlitPath caches for every unsubmitted encoder, and fixture discard retries its environment bake. The patch depends on that contract. It preserves original static camera, Sun, material, texture and terrain-shadow dirty triggers, and rebuilds legacy content when the mode changes. No shadow-refresh reduction is proposed.

Remaining acceptance gates are substantial: full Intel shader exactness, explicit 16-texture pipeline-layout validation, native cache lifecycle test execution, complete engine frame equivalence and clean same-scene GPU/FPS A/B. The new entry specializes visibility to 1 and adds a half-format roundtrip, so arithmetic specialization and rare boundary rounding must be checked on the target driver.

No broad build was started. Minimal WASM source impact is blit_path.cpp, environment_lighting.cpp and application.cpp. A source scan finds the full BlitPath header only in blit_path.cpp and application.cpp; application.hpp forward-declares the class and stores a unique_ptr, so Application size and the unchanged debug_overlay/wasm-entry consumers do not change. Future isolated packaging must explicitly replace the frozen ray shader preload and rebuild all full-type allocation consumers. Preserve the original query source and the separately retained CPU mesh changes when creating a coherent future candidate.
